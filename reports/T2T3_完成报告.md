## 一、T2 情绪头：本次最大收获

### 结果（val 2354 条，calib/test 各半，指标报在 test 上）

| 数据集 | Accuracy | Macro-F1 |
|---|---|---|
| calib（调参） | 0.6992 | 0.5878 |
| **旧 test（仅诊断）** | **0.7290** | **0.6466** |
| 全 val | 0.7141 | 0.6221 |

### 与基线对比（统一为完整 val，历史记录）

| 方案 | Accuracy | Macro-F1 |
|---|---|---|
| 多数类（恒答 anxiety） | 0.3190 | 0.0302 |
| 词典规则层 | 0.2587 | 0.1061 |
| **T2 情绪头** | **0.7141** | **0.6221** |

**完整 val 上相对多数类提升约 39.5 个百分点，相对规则层提升约 45.5 个百分点。**
这直接证实了 T1 的判断：**词典规则在这套 16 类体系上不可用，必须重训分类器**——现在它被替换掉了。

### 训练配置（可复现）

```bash
python tools/train/train_multitask.py \
  --base models/chinese-roberta-wwm-ext \   # 102M 参数
  --epochs 1 --batch-size 16 --max-length 256 \
  --freeze-layers 6 --lr 3e-5 --threads 16 --tag v1
```
- 共享编码器 + 4 个头（情绪 16 类 CE 带类别权重；画像 3 组 BCE）
- 18,653 条，1 epoch = 1,166 步，**耗时 4,776 秒（约 80 分钟）**，纯 CPU
- 产出：`models/t2_multitask/best.pt`（约 410 MB）
- 类别不均衡已由加权 CE 解决：**先验校正温度自动搜出 tau=0**（即不需要额外校正）

### 踩到并修掉的关键 bug
**截断方向**：默认 `tokenizer(truncation=True)` 保留前缀、丢弃末尾，而 `history` 是"最近的对话在末尾"，
结果**把最关键的最后一句用户发言切掉了**，情绪判断失去依据。已改为 token 级保留末尾 max_length 个 token 并保住 `[CLS]`。

## 二、T2 画像头：未达标，且诊断结论是"信号不足"

### 结果

| 字段 | test P | test R | **test F1** | test 全对率 | 0.5 阈值下 F1 |
|---|---|---|---|---|---|
| personality_traits | 0.160 | 0.389 | **0.227** | 0.247 | 0.000 |
| interests | 0.054 | 0.365 | **0.094** | 0.206 | 0.000 |
| style | 0.193 | 0.561 | **0.287** | 0.118 | 0.000 |

### 两个工作点（官方指标未知，两个都给了）

| 工作点 | 三组全对率(test) | 适用场景 |
|---|---|---|
| A 逐标签阈值（优化 F1） | 0.0331 | 官方按分字段 F1 计分 |
| B 全局阈值 0.55（优化全对率） | **0.2090** | 官方按完全一致计分 |
| **参考：全空画像（同一旧 test）** | **0.2090** | 保守兜底 |

**旧工作点 A 低于全空基线；B 的预测全部为空，与同一旧 test 的全空基线相同，没有增益。** 完整 val 的 0.3717 不可与旧 test 的 0.2090 直接比较。

### 诊断（`tools/train/diagnose_profile.py`）

| 字段 | 平均 AUC | 平均最佳可达 F1 | 最高频组合 | 占比 |
|---|---|---|---|---|
| personality_traits | 0.615 | 0.125 | **空集** | 61.9% |
| interests | 0.591 | 0.077 | **空集** | 74.9% |
| style | 0.605 | 0.136 | **空集** | 51.7% |

**AUC 只有 0.59–0.62，接近随机。** 少数标签略有信号（`pets` 0.72、`conservative` 0.67、`sensitive` 0.63、`direct` 0.65），
但 `film_animation` 0.42、`casual` 0.45、`travel_outdoor` 0.48 基本是噪声。

**当前模型在一次训练和 256 token 输入下，未学到足够画像信号。** 低 AUC 不能证明输入本身没有信息，也不能确定标注来源；长上下文、任务权重和输入构造仍需要验证。

### 建议（重要）

1. **默认输出空画像**，除非官方指标确认是"分字段 F1"再切到工作点 A；
2. 先对长上下文、任务权重和输入构造做有控制的小实验，再决定训练投入；
3. **必须问组委会两件事**：画像的**评分方式**，以及画像标签的**标注来源**（是否可从对话推断）；
4. 若确认可从对话推断，下一轮再试：上下文加到 512+ token、BCE 加 `pos_weight`、把画像头拆成独立模型训练。

## 三、T3 回复生成：全流程已打通，效果待 GPU

### 已跑通的链路（本机 CPU 验证）

```
官方语料 → LoRA SFT → 合并/适配器 → 生成预测 → 官方四字段组装 → 评分器打分
```

冒烟配置：Qwen2.5-0.5B-Instruct，200 条样本，24 优化步，**989 秒**，LoRA 可训练参数 8.80M / 502.8M（1.75%）。

生成 20 条 val 实例（CPU 7.2 秒/条），官方评分器结果：

| 指标 | 冒烟模型（20 条） | 持久化基线（完整 val） | 参考 |
|---|---|---|---|
| ROUGE-1 | 0.2823 | 0.3851 | — |
| ROUGE-L | 0.1597 | 0.1987 | 目标 > 0.199 |
| char-BLEU-4 | 0.0365 | 0.0512 | — |
| 平均长度 | 110.1 字 | 160.0 | 参考 237.6 |

上述两个文件覆盖的子集不同，不能据此判断严格优劣；后续必须在同一子集比较。模型只训了 24 步，这一步证明了管线可用，并暴露真实训练要解决的问题：

从生成样例中观察到的失败模式（正是 7B 全量训练要修掉的）：
1. **复制用户用词并循环**：`"他跑在我前面"…"原地踏步"…"他跑在我前面"` 反复自我引用；
2. **主动给建议**（第一条就列了 4 条编号步骤），而参考回复是先把情绪接住；
3. **臆造事实**：`"这种'只改'式的'倒出来'其实是一种自我疗愈的方式"`；
4. 长度偏短（110 字 vs 参考 238 字）。

### 7B 全量训练：手册已就绪，需 GPU

见 `docs/T3_训练运行手册.md`，含：
- 完整命令（LoRA r=32 / alpha=64 / lr 1e-4 / 2 epochs / bs 2 × accum 8 / max_len 1536）
- 显存与卡时预算表（1×A100 40G 约 **5.5 卡时**；1×4090 24G 约 7 卡时）
- 合并 + AWQ 量化命令
- DPO 偏好对齐（0.5–1 卡时，专治"建议给太早"）
- 6 个已知坑（截断方向、pad_token、labels 屏蔽、离线加载、checkpointing、采样不可复现）

**卡时分配建议**：SFT 5–7 + DPO 0.5–1 + 联调录制 8–10 = 14–18 卡时，20 卡时够用。

### T3 冒烟中修复的 bug
`SFTDataset` 原来用 `(p_ids + t_ids)[:max_len]` 截断，样本超长时**把目标回复截掉了**，
导致 labels 全为 -100，交叉熵产生 **NaN 并毁掉权重**。已改为：先保目标、再从左裁 prompt。

## 六、诚实声明

- 本机**无 GPU**，T3 的 7B 训练未实际执行，只验证了 0.5B 的完整管线；
- T2 画像头的结论建立在**一次训练**之上；虽已用 AUC 诊断支撑"信号不足"的判断，但未穷尽所有输入构造方式；
- 旧阈值只在前半集上调，但检查点用全 val 选优，且会话切分存在交叉，不能称为独立 test。修正版改为会话分组校准；后续训练使用同一 calib 选优并保留 holdout；
- 文本指标（ROUGE/BLEU）只是粗代理，真实评分很可能是 LLM-as-judge，需要用 T5 的评审脚本补充。
