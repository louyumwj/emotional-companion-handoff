## 3. LoRA SFT（主训练）

```bash
# 单卡 A100 40G / 4090 24G 均可；显存不足就调小 batch 并加大 grad-accum
python tools/train/train_sft.py \
  --model models/Qwen2.5-7B-Instruct \
  --data data/processed/views/train_resp_sft.jsonl \
  --epochs 2 \
  --gradient-checkpointing \
  --batch-size 2 --grad-accum 8 \
  --max-len 1536 \
  --lr 1e-4 \
  --lora-r 32 --lora-alpha 64 --lora-dropout 0.05 \
  --out models/t3_lora --tag v1
```

**关键参数说明**

| 参数 | 取值 | 理由 |
|---|---|---|
| `--max-len 1536` | 1536 | 参考回复中位 129 字、75 分位 243 字；加上多轮历史，1536 足够且省显存 |
| `--lora-r 32` + `alpha 64` | | 比 r=8 更强的适配能力；数据量 1.8 万条撑得住 |
| `--lr 1e-4` | | LoRA 常规学习率；全参才用 1e-5 级别 |
| `--epochs 2` | | 一轮欠拟合、三轮易过拟合（数据风格高度同质） |
| `--batch-size 2 × grad-accum 8` | 等效 batch 16 | 先启用 checkpointing 并做小步显存测试，再确定 batch；24G 能否容纳未经实测 |

**显存与卡时预算**

以下是旧阶段估算，未经 GPU 验证；不得视为显存或耗时保证。先做 10~20 步实测。

| 配置 | 显存占用 | 速度 | 2 epoch 卡时 |
|---|---|---|---|
| 1×A100 40G，bs 4 × accum 4 | ~32 GB | ~2.5 it/s | **约 5.5 卡时** |
| 1×4090 24G，bs 2 × accum 8 | ~22 GB | ~1.8 it/s | 约 7 卡时 |
| 1×A100 80G，bs 8 × accum 2 | ~55 GB | ~4 it/s | 约 3.5 卡时 |

**建议排期**：SFT 5–7 卡时，DPO 0.5–1 卡时，联调/录视频留 8–10 卡时。**20 卡时够用但别浪费在试错上**——先在 0.5B 上把超参试对。

**省显存开关**：脚本默认 `use_cache=False`；GPU 训练命令建议加 `--gradient-checkpointing`，该参数同时启用：
```python
model.gradient_checkpointing_enable()
model.enable_input_require_grads()   # peft + checkpointing 必须
```

## 4.（可选）DPO 偏好对齐

SFT 之后做一轮 DPO，专治"给建议给太早"：

1. 用 v1 模型对同一批 prompt 采样 4 条回复；
2. 用评审模型（Qwen2.5-72B 或 DeepSeek）按"是否先共情、是否说教"排序；
3. 组 (chosen, rejected) 对，跑 `trl.DPOTrainer`，β=0.1，1 epoch，lr 5e-6。

预计 0.5–1 卡时，收益主要在"不轻易给建议"这一条风格约束上。

## 5. 合并与量化

```bash
# 5.1 合并 LoRA 到基座
python - <<'PY'
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer
base = "models/Qwen2.5-7B-Instruct"; ad = "models/t3_lora/v1"; out = "models/t3_merged"
m = AutoModelForCausalLM.from_pretrained(base, torch_dtype="auto", device_map="cpu")
m = PeftModel.from_pretrained(m, ad).merge_and_unload()
m.save_pretrained(out, safe_serialization=True)
AutoTokenizer.from_pretrained(base).save_pretrained(out)
PY

# 5.2 AWQ 4bit 量化（约 5 GB，评测镜像友好）
lmdeploy lite auto_awq models/t3_merged --work-dir models/t3_awq --w-bits 4 --w-group-size 128
```

## 6. 生成预测 + 自评

```bash
# 生成（本地 CPU 也能跑，只是慢；GPU 上 --limit 可放大到全量 2354 条）
python tools/train/infer_sft.py \
  --model models/Qwen2.5-7B-Instruct \
  --adapter models/t3_lora/v1 \
  --data data/processed/official_val.jsonl \
  --limit 2354 \
  --t2-pred reports/t2_pred_val.jsonl \
  --out reports/t3_pred_val.jsonl

# 官方四字段评分
python tools/eval/official_scorer.py \
  --pred reports/t3_pred_val.jsonl \
  --gold data/processed/official_val.jsonl \
  --out reports/T3_报告.md
```

`--t2-pred` 会把 T2 预测的情绪/画像作为**生成条件**注入 system prompt，并用分类头的输出**覆盖**最终 `emotion_label` 字段（分类头有概率校准，比生成式输出稳）。

## 7. 已知坑（本地冒烟时踩到的）

| 坑 | 现象 | 处理 |
|---|---|---|
| **截断方向反了** | 默认保留前缀会丢掉最新用户发言 | T2 保留末尾并保住 `[CLS]`；T3 训练裁 prompt 开头，推理显式 `truncation_side="left"` 保留末尾 |
| `pad_token` 为空 | Qwen 无 pad token，batch 报错 | 脚本已设 `tok.pad_token = tok.eos_token` |
| labels 未屏蔽 prompt | 模型学会复述用户的话 | 已修：prompt 部分 label 置 -100，只对回复算 loss |
| 镜像里离线加载 | 评测环境无外网 | 训练/推理均用本地路径，`HF_HUB_OFFLINE=1` |
| peft + gradient checkpointing | 报 "element 0 of tensors does not require grad" | 加 `enable_input_require_grads()` |
| 采样导致结果不可复现 | 每次评测分数不同 | 推理用 `do_sample=False`（脚本默认贪心） |

## 8. 验收标准

| 指标 | 门槛 | 说明 |
|---|---|---|
| ROUGE-L | > 0.199 | 必须超过"复述上一句助手发言"的持久化基线 |
| 平均回复长度 | 80–200 字 | 参考中位 99 字；太短像敷衍，太长像说教 |
| 不主动给建议率 | 用户明确说"别给建议"时必须不给 | 语料里有这类样本，可直接构造测试 |
| 情绪字段 | 由 T2 分类头提供 | 见 `reports/T2_报告.md` |
| 端到端延迟 | P95 < 3 s | 评测大概率卡超时 |
