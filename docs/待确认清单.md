# 提交镜像前必须向组委会/平台确认的问题清单

> 这些问题的答案会直接改变镜像设计（体积、依赖、接口、启动方式），
> 建议在赛事群里一次性问清，或从咪咕仝学的参赛手册里逐条核对。

## A. 镜像与运行时

1. **是否必须基于官方「赛事基础镜像」构建？**基础镜像名 / tag 是什么？
2. **私有镜像体积上限**是多少（含权重）？是否有分层缓存/配额限制？
3. **镜像提交方式**：推送到平台镜像仓库，还是上传 tar 包？单文件是否有大小限制？
4. **单实例可用卡型与显存**？是否保证 GPU（型号 / 显存）？是否允许 `--gpus all`？
5. **是否允许运行时访问外网**？（若允许，可把权重放对象存储；若不允许，权重必须进镜像）
6. **容器启动超时**是多少秒？（决定能不能用 7B + LMDeploy）
7. **是否限制端口、进程数、共享内存**（`--shm-size`，vLLM 常因此崩）？
8. 评测环境是 **x86_64** 吗？CUDA 驱动版本是多少？

## B. 评测接口契约（最关键）

9. **调用方式**：OpenAI 兼容（`/v1/chat/completions`）还是自定义 REST？
10. 请求/响应的 **完整字段定义**有没有示例？是否要求返回 JSON 结构（情绪标签等）？
11. **多轮**如何组织：靠 `messages` 数组传入，还是靠 `session_id`/`user_id` 服务端维护？
12. 评测**并发**是多少（单请求串行 / 多用户并发）？**单请求超时**多少秒？
13. 是否要求 `/health` 或特定健康检查路径？
14. 评测是否包含 **语音 / 数字人形象**输入输出？（纯文本 or 多模态，影响是否要接 ASR/TTS/口型驱动）

## C. 评分与数据

15. 「数字人综合情感陪伴对话模型」的**评分维度与权重**是什么？
    （常见：共情准确性、情绪识别、长记忆一致性、安全性、回复质量、时延）
16. 是否使用**公开基准**（如 ESConv / 自建测试集）？评测集能否提前拿到样例？
17. 「长记忆」的考察方式：同会话内多轮，还是**跨会话/跨容器重启**？
18. 是否有**安全红线**（自伤、涉政、涉黄等）触发即扣分或取消资格？
19. 伦理与数据合规要求：是否要求提供用户知情同意、数据脱敏说明？

## D. 算力与训练

20. 20 卡时（初赛）的**卡型与计时规则**（按卡×小时还是按墙钟）？是否可续？
21. 平台是否提供**数据集与预置模型**？是否有官方 baseline 仓库？
22. 是否允许使用第三方开源模型权重？**是否要求在作品中声明模型来源与许可证**？
