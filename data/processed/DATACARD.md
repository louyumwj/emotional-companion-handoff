## 一、任务定义（重要：这不是自由对话）

官方给的**不是**聊天语料，而是**结构化多任务预测**：在每条会话的指定位置（prediction point）预测四样东西。

```
输入                                        输出（target）
conversation_id                             response_text     ← 助手该说什么
turns[]  （截断到 target_user_turn_id）      emotion_label     ← 用户此刻情绪（16 类）
prediction_points[]                         user_profile      ← 用户画像（3 个多标签数组）
  ├ target_user_turn_id                     memory_refs       ← 引用的记忆 ID（mem_NNNNNN）
  └ assistant_response_turn_id
```

**⚠️ 最关键的坑**：公开文件里 `turns[]` **已经包含了待预测的那条助手回复**——
train 18,657/18,657 条、val 2,354/2,354 条，`target.response_text` 与 `turns` 中同轮内容**完全一致**。
说明推理时该轮会被抹掉。**所有训练数据的构造必须截断到 `target_user_turn_id`**，否则模型学到的是"抄上下文"，线上直接崩。

本仓库的 `tools/data/build_official_dataset.py` 已按此规则构造实例。

## 二、规模

| 项 | train | val |
|---|---|---|
| 会话数 | 8,338 | 900 |
| 总轮次 | 117,902 | 11,732 |
| 预测点数 | 18,657 | 2,354 |
| 规范化实例数（剔除 4 条异常） | **18,653** | **2,354** |
| 每会话轮次（中位/最大） | 12 / 50 | 10 / 50 |
| 每会话预测点（中位/最大） | 2 / 8 | 3 / 9 |
| 用户发言长度（中位） | 64 字 | 67 字 |
| 参考回复长度（中位/均值） | 129 / 218 字 | 99 / 158 字 |

**结构规律**（已全部验证）：
- `target_user_turn_id` **恒为奇数**（18,657/18,657），即预测点永远落在用户轮
- `assistant_response_turn_id = target_user_turn_id + 1`（仅 4 条例外，已剔除）
- **13,043/18,657（70%）的预测点之后还有对话内容** → 推理必须截断，不能喂全量
- 589 个预测点落在第 1 轮（**完全无历史**，冷启动场景）

## 三、四个预测字段的分布

### 1. 情绪标签（16 类，严重不均衡）

| 标签 | train 占比 | 标签 | train 占比 |
|---|---|---|---|
| **anxiety** | **34.0%** | neutral | 3.5% |
| relaxed | 15.1% | pride | 1.3% |
| helplessness | 8.4% | joy | 0.9% |
| fear | 7.4% | disgust | 0.7% |
| sadness | 5.8% | care | 0.4% |
| mixed | 5.1% | surprise | 0.3% |
| loneliness | 4.7% | | |
| anger | 4.6% | | |
| shame | 4.0% | | |
| gratitude | 3.7% | | |

**多数类基线 34.0%**。注意：`anxiety`+`helplessness`+`fear`+`sadness`+`loneliness`+`shame` 六类负面合计 **63.9%**，与"大学生心理陪伴"的产品定位一致。

### 2. 用户画像（3 个多标签数组，高度稀疏）

| 字段 | 取值域 | 空值率 | 数组长度分布 |
|---|---|---|---|
| `personality_traits` | 10 类 | **56.3%** | 0:56% / 1:29% / 2:14% / 3:0.5% |
| `interests` | 12 类 | **69.3%** | 0:69% / 1:28% / 2:2% |
| `style` | 11 类 | **46.8%** | 0:47% / 1:44% / 2:9% |

Top 取值：`sensitive`(5165) `high_conscientiousness`(2281) `conservative`(1364) ／ `career_development`(1472) `social`(764) `study_exam`(746) ／ `rational`(4418) `direct`(2603)。

**同一会话内画像一致率仅 64.1%** → 画像不是固定属性，而是"截至当前推断出来的状态"，必须**逐预测点预测**，不能一会话一算。

### 3. 记忆引用（⛔ 最大风险点）

- 每个预测点引用 **0~9 个**记忆 ID，中位数 2（0 个的仅占 **2.3%**）
- train 出现 **26,883** 个不同 ID，范围 `mem_000001 ~ mem_044990`（缺失率 40.2%）
- **编号是构建期分配的全局计数器**：每个会话占一段连续区间
  （如 `train_conv_000001` → mem_000001~000006，`train_conv_000002` → mem_000121~000123，`train_conv_000003` → mem_000128~000131）
- train 与 val 的 ID 区间**互相重叠**（train 1~44,990，val 3,603~42,530）→ 随机切分，不是时序切分
- **公开文件里没有任何地方定义记忆 ID 对应的内容**（schema 无 `memories` 字段）

> **结论：公开输入中没有记忆 ID 到内容的映射，目前无法构造可靠的语义检索方案。** 是否存在其他可用输入或规则，需由组委会确认；“数学上不可预测”不能由现有证据证明。全空基线 F1 实测为 0，但随机猜测的期望值并非严格等于 0。
> **这是必须向组委会确认的第一个问题**（见 `docs/待确认清单.md` 更新项）。

### 4. 回复文本

中位 129 字、均值 218 字，明显长于 EmoLLM 语料（均值 157 字），风格是**高精度情绪镜映 + 不轻易给建议**，
例如：

> 用户：`先别给我分析要怎么观察或者权衡了，我现在其实不太想听这些建议。`
> 助手：`明白，先不谈怎么办。就是那种别扭：一冷下来，就不只是两个人之间的事，连自己在这圈子里是不是还站得住，都跟着晃了一下。这种发虚的感觉本身就够难受的。`

**这条数据质量很高**，是罕见的"去说教"中文心理陪伴语料——**单就这份数据，价值超过之前找到的所有开源语料**。

## 四、零训练基线（地板分，必须超过）

`tools/eval/baselines.py`，在 val 2,354 条上：

| 方案 | 情绪 Acc | 情绪 Macro-F1 | 画像全对率 | 记忆 F1 | ROUGE-L |
|---|---|---|---|---|---|
| B0 恒答 `anxiety` + 画像/记忆/回复全空 | **31.9%** | 0.030 | **37.2%** | 0.000 | 0.000 |
| B1 规则情绪（`app/emotion.py`）+ 空画像 + 回复取上一条助手发言 | 25.9% | 0.106 | **37.2%** | 0.000 | 0.199 |
| B2 B1 + 关键词抽画像 | 25.9% | 0.106 | **0.25%** | 0.000 | 0.199 |

**三条硬结论：**

1. **现有的词典规则情绪层不能用**：25.9% 比"永远答焦虑"的 31.9% 还差。原因是 7 类词典体系 ≠ 官方 16 类体系，且它倾向输出 `neutral`（实测 160 次把 anxiety 判成 neutral）。**T2 必须用官方标签重训分类器。**
2. **画像要"宁可少报不可多报"**：全空的画像竟然能拿 37.2% 全对率（因为多数点确实为空）；而关键词硬抽会把全对率从 37.2% 打到 **0.25%**。正确做法是**带阈值校准的多标签分类**，同时看"全对率"和"分字段 F1"两个指标。
3. **记忆引用是纯送分或纯丢分**：不解决记忆库来源，这 1/4 的字段恒为 0。
